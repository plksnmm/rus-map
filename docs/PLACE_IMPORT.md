# Закрытый импорт мест

## Назначение

Команда `rus_map.admin.place_import` добавляет заранее проверенные точки в
`app.places`. Она запускается только локально или внутри backend-контейнера и не
создаёт нового HTTP endpoint. Публичные изменяющие запросы на staging остаются
заблокированными Caddy.

У текущей модели места нет статуса `pending_review`. Поэтому этот импортёр нельзя
использовать непосредственно для пользовательских заявок. Перед добавлением
название, описание, координаты и источники проходят проверку в отдельной ветке и
Pull Request.

## Формат манифеста

Файл сохраняется как UTF-8 JSON:

```json
{
  "schema_version": 1,
  "places": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "title": "Кусковский химический завод",
      "description": "Проверенная историческая справка.",
      "latitude": 55.74,
      "longitude": 37.75
    }
  ]
}
```

Правила:

- `schema_version` сейчас всегда равен `1`;
- `places` содержит хотя бы одну точку;
- UUID создаётся заранее и никогда не переиспользуется для другого объекта;
- название после удаления пробелов по краям содержит от 1 до 200 символов;
- описание может быть `null` или строкой длиной до 10 000 символов;
- широта находится в диапазоне от −90 до 90;
- долгота находится в диапазоне от −180 до 180;
- UUID внутри одного файла не повторяются;
- неизвестные поля запрещены.

Импортёр преобразует координаты в PostGIS `geometry(Point,4326)`. Внутри
геометрии используется стандартный GIS-порядок `longitude latitude`, хотя в JSON
поля названы отдельно и записаны в привычном порядке.

## Стабильность и конфликты

Идентичный повторный запуск ничего не создаёт. Для существующего UUID импортёр
сравнивает название, описание и координаты. Погрешность координат до `1e-7`
градуса допускается только для стабильного преобразования чисел базой.

Любое содержательное расхождение считается конфликтом. Инструмент намеренно не
обновляет и не удаляет существующие точки: сначала нужно выяснить, исправляется
ли ошибка, меняется ли официальное название или обнаружен дубликат реального
объекта.

## Создание UUID

В PowerShell:

```powershell
[guid]::NewGuid()
```

UUID фиксируется в манифесте до первого импорта. Не следует генерировать новый
UUID при каждом запуске — это создаст дубликаты одной точки.

## Локальная проверка

После запуска базы и настройки `.env`:

```powershell
docker compose up -d db
uv run python -m rus_map.admin.place_import `
  --file .\path\to\places.json `
  --dry-run
```

Успешный результат:

```text
Dry run successful: places created=1, already existed=0.
```

Dry-run выполняет валидацию и реальные запросы к базе, но завершает транзакцию
rollback. Для локальной записи убрать только `--dry-run`.

## Импорт на staging

Перед записью создать и проверить свежую резервную копию по `docs/BACKUPS.md`.
Затем из `/opt/rus-map` передать проверенный файл в контейнер через stdin:

```bash
docker compose --env-file .env.production -f compose.production.yml exec -T backend \
  python -m rus_map.admin.place_import --file - --dry-run < places.json
```

Если dry-run успешен, импортировать тот же неизменённый файл:

```bash
docker compose --env-file .env.production -f compose.production.yml exec -T backend \
  python -m rus_map.admin.place_import --file - < places.json
```

Повторить импорт и убедиться, что итог сообщает `created=0` и
`already existed` равен числу мест в файле.

## Проверка результата

Получить список мест:

```bash
curl -fsS "https://vm-1703.lnvps.cloud/rus-map/api/v1/places"
```

Проверить конкретную карточку:

```bash
curl -fsS \
  "https://vm-1703.lnvps.cloud/rus-map/api/v1/places/PLACE_UUID"
```

После этого нужно обновить карту, найти новый маркер, открыть карточку и сверить
название, описание и положение. Публичный POST должен продолжать возвращать 403.

## Коды завершения

- `0` — dry-run или импорт завершён успешно;
- `1` — файл не читается, JSON невалиден либо найден конфликт;
- `2` — неверно указаны аргументы командной строки.

При ошибке текущая транзакция откатывается целиком. Конфликт нельзя обходить
ручным SQL или заменой UUID без расследования причины.
