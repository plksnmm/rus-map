# Архитектура

## Текущее состояние

Приложение представляет собой Python-пакет с `src`-структурой. FastAPI создаётся
функцией-фабрикой `create_app()` в `src/rus_map/main.py`. Версионированные
маршруты собираются общим роутером `src/rus_map/api/router.py`, а модели HTTP API
находятся в `src/rus_map/schemas`. Отдельный одностраничный веб-клиент находится
в каталоге `frontend` и собирается Vite.

```text
src/rus_map/       код приложения
  admin/           закрытые CLI-команды без HTTP-маршрутов
  api/             HTTP-маршруты и общий API-router
  db/              engine, sessions и база ORM-моделей
  repositories/    SQLAlchemy-запросы и преобразование строк базы
  schemas/         Pydantic-схемы запросов и ответов
migrations/        история изменений схемы PostgreSQL
tests/             автоматические тесты
docs/              проектная документация
pyproject.toml     метаданные, зависимости и настройки инструментов
uv.lock            зафиксированные версии зависимостей
frontend/          React/TypeScript-клиент и его npm-зависимости
```

Фабрика приложения отделяет создание FastAPI-объекта от его запуска. Это
позволит позднее создавать приложение с тестовой конфигурацией и подменёнными
зависимостями. Frontend использует React для компонентов, Bootstrap для
интерфейса и MapLibre GL JS для WebGL-карты. Сейчас карта отображает внешнюю
тёмную подложку OpenFreeMap с русскими подписями. Краткие данные мест загружаются
из API и отображаются маркерами; клик по маркеру запрашивает полную карточку.
Материалы карточки загружаются отдельным запросом, поэтому их ошибка не скрывает
название, описание, карту или маркеры.

## Реализованный HTTP API

### `GET /health`

Назначение: подтвердить, что процесс приложения способен принимать HTTP-запросы.

Успешный ответ имеет статус `200 OK`:

```json
{"status": "ok"}
```

Endpoint пока не проверяет базу данных или внешние сервисы.

### `GET /api/v1/places`

Назначение: вернуть коллекцию мест для отображения на карте. Endpoint получает
`PlaceRepository` через FastAPI dependency, читает места из PostgreSQL и
преобразует результат в публичную Pydantic-схему.

Подробный контракт приведён в `docs/API.md`.

### `GET /api/v1/places/{place_id}`

Назначение: вернуть полные данные выбранного места для карточки. Endpoint
получает UUID из пути, читает одну запись через `PlaceRepository` и возвращает
описание, координаты и временные метки. Отсутствующая запись возвращает 404.

### `GET /api/v1/places/{place_id}/materials`

Назначение: вернуть опубликованные материалы существующего места. Отдельный
`MaterialRepository` проверяет существование места, фильтрует статусы материала
и редакции и оконной функцией выбирает последнюю опубликованную редакцию. Новые
непроверенные редакции не раскрываются и не скрывают старую одобренную версию.

## Локальная инфраструктура данных

`compose.yml` запускает PostgreSQL 18 с PostGIS 3.6. Данные сохраняются в named
volume `postgres_data`. На Windows порт базы доступен только локально по адресу
`127.0.0.1:15432`; внутри Docker-сети PostgreSQL использует стандартный порт
`5432` и имя сервиса `db`.

Доступ к базе подготовлен через асинхронные SQLAlchemy engine и sessions.
Конфигурация загружается через Pydantic Settings, пароль хранится как SecretStr,
а URL собирается объектом SQLAlchemy `URL`. Alembic получает тот же URL и
metadata класса `Base`; пароль не дублируется в `alembic.ini`.

ORM-таблицы проекта принадлежат отдельной схеме PostgreSQL `app`. Это отделяет
данные приложения от служебных таблиц PostGIS, которыми Alembic управлять не
должен.

Модель `Place` хранится в `app.places`. Координаты представлены типом PostGIS
`geometry(Point,4326)` и защищены пространственным GiST-индексом. Repository
выполняет один асинхронный запрос: `ST_Y` и `ST_X` извлекают координаты, а
оконный `count()` возвращает общее количество мест.

Отдельный запрос по UUID возвращает полную запись места. Список остаётся
компактным и пригодным для одновременной отрисовки множества маркеров, а более
тяжёлые данные карточки загружаются только после выбора пользователем.

Создание места выполняется одним `INSERT ... RETURNING`. PostGIS Point строится
в порядке longitude, latitude и получает SRID 4326. FastAPI dependency задаёт
границу транзакции на один HTTP-запрос: успешный запрос завершается commit,
исключение — rollback, после чего session закрывается.

## Планируемые компоненты

Этот раздел описывает направление, а не уже реализованное состояние:

- редактирование и удаление мест через API;
- отдельные модули маршрутов, пользователей и административной модерации;
- S3-совместимое хранилище фотографий;
- ссылки между местами и отдельными фото-, видео- и текстовыми материалами;
- поиск мест по названию через API с выбором результата и перемещением карты к
  соответствующему маркеру;
- фоновые задачи для обработки изображений и внешних материалов.

## Сохранение истории материалов

Место и сведения о нём должны иметь разные жизненные циклы. `Place` представляет
устойчивую точку карты с постоянным UUID. Тексты, ссылки, фотографии, видео,
аудио, новости и репортажи будут храниться отдельными записями `Material`,
связанными с местом.

Основное правило: новая информация добавляется, а не заменяет уже опубликованную.
Если пользователь прислал ещё один репортаж о существующем заводе, после
модерации создаётся новый материал у того же места. Если исправляется ранее
добавленный текст, создаётся новая редакция материала; предыдущая редакция
остаётся доступна в истории с автором и временем изменения.

Обычное удаление будет логическим: материал получает статус `archived` или
`rejected` и перестаёт показываться публично, но сохраняется для аудита. Физическое
удаление допустимо только для специальных случаев — например, требования
правообладателя, персональных данных или вредоносного файла — и должно отдельно
журналироваться.

Реализованная основа потока:

```text
место -> материал (статус) -> редакции материала (собственный статус)
                                  |
                                  +-> pending_review -> published
                                                     -> rejected / archived
```

Таблицы `app.materials` и `app.material_revisions` созданы отдельной миграцией.
Материал и каждая редакция имеют независимый статус. Поэтому новая редакция может
ожидать проверки, пока публичный API продолжает возвращать предыдущую
опубликованную редакцию. Публичное создание и административная модерация пока не
реализованы.

Для доверенного первоначального наполнения реализован закрытый импорт JSON через
`rus_map.admin.material_import`. Это не HTTP endpoint: команда запускается из
локальной консоли или внутри backend-контейнера. Pydantic сначала проверяет весь
документ, затем импортёр сопоставляет стабильные UUID с базой и добавляет записи
в одной транзакции. Идентичный повторный запуск ничего не дублирует, а конфликт
UUID или номера редакции откатывает весь запуск. Режим `--dry-run` выполняет те
же проверки и SQL-запросы, но всегда завершает транзакцию rollback.

Тот же подход используется модулем `rus_map.admin.place_import` для новых точек.
Он принимает стабильные UUID, проверяет земные диапазоны координат и сохраняет
`geometry(Point,4326)` в порядке longitude/latitude. Для существующего UUID
название, описание и координаты сравниваются с базой; расхождение считается
конфликтом, а не разрешением на перезапись.

У `Place` пока нет статуса модерации. Поэтому CLI импортирует только заранее
проверенные в Pull Request административные манифесты. Будущие пользовательские
предложения должны попадать в отдельную очередь премодерации, а не напрямую в
`app.places`.

Внешние ссылки не превращаются в HTML внутри произвольного описания. Frontend
проверяет структуру ответа материалов и повторно разрешает только протоколы
HTTP/HTTPS. Ссылки открываются в новой вкладке с защитными атрибутами `noopener`
и `noreferrer`. Текст выводится средствами React без `dangerouslySetInnerHTML`.
Изображение может отображаться как ленивое превью и одновременно остаётся
ссылкой на оригинал; видео и аудио пока не встраиваются со сторонних сайтов, а
открываются отдельной ссылкой.

Значимые архитектурные решения фиксируются в `docs/decisions` в формате ADR.
