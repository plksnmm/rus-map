# Архитектура

## Текущее состояние

Приложение представляет собой Python-пакет с `src`-структурой. FastAPI создаётся
функцией-фабрикой `create_app()` в `src/rus_map/main.py`. Версионированные
маршруты собираются общим роутером `src/rus_map/api/router.py`, а модели HTTP API
находятся в `src/rus_map/schemas`.

```text
src/rus_map/       код приложения
  api/             HTTP-маршруты и общий API-router
  db/              engine, sessions и база ORM-моделей
  schemas/         Pydantic-схемы запросов и ответов
migrations/        история изменений схемы PostgreSQL
tests/             автоматические тесты
docs/              проектная документация
pyproject.toml     метаданные, зависимости и настройки инструментов
uv.lock            зафиксированные версии зависимостей
```

Фабрика приложения отделяет создание FastAPI-объекта от его запуска. Это
позволит позднее создавать приложение с тестовой конфигурацией и подменёнными
зависимостями.

## Реализованный HTTP API

### `GET /health`

Назначение: подтвердить, что процесс приложения способен принимать HTTP-запросы.

Успешный ответ имеет статус `200 OK`:

```json
{"status": "ok"}
```

Endpoint пока не проверяет базу данных или внешние сервисы.

### `GET /api/v1/places`

Назначение: вернуть коллекцию мест для отображения на карте. Сейчас endpoint
фиксирует контракт и возвращает пустую коллекцию; источник данных будет добавлен
следующим этапом.

Подробный контракт приведён в `docs/API.md`.

## Локальная инфраструктура данных

`compose.yml` запускает PostgreSQL 18 с PostGIS 3.6. Данные сохраняются в named
volume `postgres_data`. На Windows порт базы доступен только локально по адресу
`127.0.0.1:15432`; внутри Docker-сети PostgreSQL использует стандартный порт
`5432` и имя сервиса `db`.

Доступ к базе подготовлен через асинхронные SQLAlchemy engine и sessions.
Конфигурация загружается через Pydantic Settings, пароль хранится как SecretStr,
а URL собирается объектом SQLAlchemy `URL`. Alembic получает тот же URL и
metadata класса `Base`; пароль не дублируется в `alembic.ini`.

ORM-таблицы проекта принадлежат отдельной схеме PostgreSQL `app`. Это отделяет
данные приложения от служебных таблиц PostGIS, которыми Alembic управлять не
должен.

Модель `Place` хранится в `app.places`. Координаты представлены типом PostGIS
`geometry(Point,4326)` и защищены пространственным GiST-индексом. Маршруты
FastAPI пока не используют database sessions; подключение API к модели будет
отдельным вертикальным этапом.

## Планируемые компоненты

Этот раздел описывает направление, а не уже реализованное состояние:

- репозиторий мест и подключение API к PostgreSQL;
- отдельные модули мест, материалов, маршрутов, пользователей и модерации;
- S3-совместимое хранилище фотографий;
- веб-клиент с интерактивной картой;
- фоновые задачи для обработки изображений и внешних материалов.

Значимые архитектурные решения фиксируются в `docs/decisions` в формате ADR.
