# Рабочий процесс разработчика

## Обычный цикл работы

1. Проверить состояние репозитория: `git status`.
2. Создать отдельную ветку от актуальной `main`.
3. Синхронизировать окружение: `uv sync`. Для frontend после изменения
   lock-файла использовать `npm ci` в `frontend`.
4. Реализовать небольшое законченное изменение.
5. Добавить или обновить тесты.
6. Обновить относящуюся к изменению документацию.
7. Отформатировать код: `uv run ruff format .`.
8. Запустить все проверки качества.
9. Просмотреть `git diff` и создать коммит.
10. Отправить ветку на GitHub и открыть Pull Request в `main`.

## Ветки и Pull Request

Ветка `main` должна содержать рабочее состояние проекта. Изменения выполняются в
короткоживущих ветках с понятными именами:

- `feature/...` — пользовательская функциональность;
- `fix/...` — исправление дефекта;
- `test/...` — тесты;
- `docs/...` — документация;
- `chore/...` — инфраструктура и обслуживание проекта.

Перед слиянием Pull Request обязательный CI должен завершиться успешно.

## Запуск приложения

```powershell
uv run uvicorn rus_map.main:app --reload
```

Флаг `--reload` перезапускает локальный сервер после изменения Python-файлов.
Он предназначен только для разработки.

Frontend запускается в отдельном терминале:

```powershell
cd frontend
npm run dev
```

Локальный адрес — <http://127.0.0.1:4173/>. Порт задан явно, поскольку стандартный
порт Vite `5173` входит в зарезервированный Windows диапазон на рабочей машине.

## Управление зависимостями

```powershell
# Зависимость приложения
uv add package-name

# Инструмент разработки или тестирования
uv add --dev package-name

# Удаление зависимости
uv remove package-name
```

После изменения зависимостей нужно добавлять в коммит и `pyproject.toml`, и
`uv.lock`.

Frontend-зависимости управляются npm из каталога `frontend`:

```powershell
npm install package-name
npm install --save-dev package-name
npm uninstall package-name
```

После изменения зависимостей frontend в коммит входят `package.json` и
`package-lock.json`. В CI применяется воспроизводимая установка `npm ci`.

## Окончания строк

Файл `.gitattributes` задаёт LF для кода, конфигурации и документации независимо
от операционной системы разработчика. Для PowerShell-скриптов используется CRLF.
Предупреждения Git вида `LF will be replaced by CRLF` обычно связаны с глобальной
настройкой `core.autocrlf`; правила репозитория имеют над ней приоритет.

## Definition of Done

Изменение считается законченным, если:

- поведение реализовано и проверено тестами;
- pytest, Ruff formatter, Ruff linter и mypy проходят;
- frontend-тесты, ESLint и production-сборка проходят;
- нет проигнорированных предупреждений;
- документация соответствует коду;
- GitHub Actions завершился успешно;
- в коммит не попали секреты, `.venv` и настройки IDE.
