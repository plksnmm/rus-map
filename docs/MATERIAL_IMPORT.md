# Закрытый импорт материалов

## Назначение

Команда `rus_map.admin.material_import` добавляет проверенные тексты и внешние
ссылки к уже существующему месту. Она предназначена для владельца проекта и не
доступна через HTTP. Публичные изменяющие запросы на staging продолжают
блокироваться Caddy.

Импорт подходит для первоначального наполнения карты и небольших проверенных
пакетов данных. Полноценная пользовательская отправка, очередь премодерации,
роли и административный web-интерфейс будут реализованы отдельно.

## Формат манифеста

Файл сохраняется как UTF-8 JSON:

```json
{
  "schema_version": 1,
  "place_id": "11111111-1111-4111-8111-111111111111",
  "materials": [
    {
      "id": "22222222-2222-4222-8222-222222222222",
      "type": "text",
      "status": "published",
      "title": "История предприятия",
      "source": "Русь пролетарская",
      "revisions": [
        {
          "id": "33333333-3333-4333-8333-333333333333",
          "revision_number": 1,
          "status": "published",
          "content": "Проверенный текст материала."
        }
      ]
    },
    {
      "id": "44444444-4444-4444-8444-444444444444",
      "type": "video",
      "status": "published",
      "title": "Видеорепортаж",
      "source": "Русь пролетарская",
      "revisions": [
        {
          "id": "55555555-5555-4555-8555-555555555555",
          "revision_number": 1,
          "status": "published",
          "url": "https://example.com/video"
        }
      ]
    }
  ]
}
```

Правила:

- `schema_version` сейчас всегда равен `1`;
- `place_id` должен принадлежать существующей точке;
- UUID каждого материала и каждой редакции задаётся заранее и не меняется;
- допустимые типы: `text`, `external_link`, `image`, `video`, `audio`;
- `text` содержит только непустой `content`;
- остальные типы содержат только полный URL с `http://` или `https://`;
- `revision_number` начинается с `1` и увеличивается внутри материала;
- неизвестные поля, повторяющиеся UUID и номера редакций запрещены;
- `source` необязателен, но желателен для атрибуции и проверки происхождения.

Статусы материала и редакции независимы. Если `status` пропущен, применяется
`pending_review`. Чтобы материал появился в публичном API, значение `published`
нужно явно поставить одновременно у материала и нужной редакции. Более новая
редакция `pending_review` не скрывает старую опубликованную.

## Создание UUID

Каждому новому объекту нужен отдельный UUID. В PowerShell:

```powershell
[guid]::NewGuid()
```

Не копировать один UUID для нескольких материалов или редакций. UUID уже
опубликованного объекта никогда не заменяется новым только из-за исправления
текста.

## Локальная проверка

База должна быть запущена, а `.env` настроен:

```powershell
docker compose up -d db
uv run python -m rus_map.admin.material_import `
  --file .\path\to\materials.json `
  --dry-run
```

`--dry-run` полностью проверяет JSON, существование места и конфликты в базе,
затем выполняет rollback. Успешный итог выглядит так:

```text
Dry run successful: materials created=2, already existed=0; revisions created=2, already existed=0.
```

Для фактической локальной записи убрать только `--dry-run`. Перед этим полезно
повторно проверить diff манифеста и убедиться, что публикация действительно
одобрена.

## Импорт на staging

Все команды выполняются на Ubuntu-сервере из `/opt/rus-map`. Сначала создать и
проверить свежую резервную копию по `docs/BACKUPS.md`.

Передача через stdin не копирует манифест внутрь постоянно работающего
контейнера:

```bash
docker compose --env-file .env.production -f compose.production.yml exec -T backend \
  python -m rus_map.admin.material_import --file - --dry-run < materials.json
```

Если dry-run успешен, импортировать тот же неизменённый файл:

```bash
docker compose --env-file .env.production -f compose.production.yml exec -T backend \
  python -m rus_map.admin.material_import --file - < materials.json
```

После импорта проверить публичный ответ:

```bash
curl -fsS \
  "https://vm-1703.lnvps.cloud/rus-map/api/v1/places/PLACE_UUID/materials"
```

Затем открыть карту, обновить страницу и вручную проверить карточку, ссылки и
изображения. Файл импорта не должен содержать паролей, токенов или иных секретов.

## Повторный запуск и конфликты

Идентичный повторный запуск безопасен. Итог покажет записи в счётчиках
`already existed`, не создавая копии.

Если существующий UUID связан с другими значениями или номер редакции уже занят
другим UUID, команда завершается ошибкой и откатывает весь пакет. Нельзя менять
UUID до тех пор, пока причина конфликта не выяснена: это могло бы создать
неразличимый дубликат.

## Исправление опубликованного материала

Опубликованная редакция не перезаписывается. В манифест того же материала нужно
оставить прежнюю редакцию без изменений и добавить новую:

```json
{
  "id": "66666666-6666-4666-8666-666666666666",
  "revision_number": 2,
  "status": "pending_review",
  "content": "Исправленный текст, который ещё проходит проверку."
}
```

После отдельной проверки новая редакция может быть импортирована сразу как
`published` только если её UUID и номер ещё отсутствуют в базе. Изменение статуса
уже импортированной записи этим инструментом намеренно считается конфликтом.
Отдельный процесс модерации появится в следующем административном слое.

## Коды завершения

- `0` — dry-run или импорт завершён успешно;
- `1` — файл не читается, JSON невалиден, место отсутствует либо найден конфликт;
- `2` — неверно указаны аргументы командной строки.

При любой ошибке записи текущего запуска откатываются. Сообщение не нужно
игнорировать или обходить ручным SQL: сначала следует понять конкретную причину.
