# Frontend

## Назначение

Frontend отображает интерактивную карту «Руси пролетарской». Он загружает
места из backend API, преобразует координаты в GeoJSON и показывает отдельный
слой маркеров. Форма добавления места относится к следующей задаче.

## Технологии

- React 19 — компоненты пользовательского интерфейса;
- TypeScript — статическая типизация;
- Vite — локальный сервер и production-сборка;
- Bootstrap 5 — сетка, базовые элементы и адаптивность;
- MapLibre GL JS — WebGL-карта;
- Vitest, jsdom и React Testing Library — компонентные тесты;
- ESLint — статический анализ frontend-кода.

Причины выбора зафиксированы в ADR
`docs/decisions/0004-use-react-bootstrap-and-maplibre.md`.

## Установка

Из корня репозитория:

```powershell
cd frontend
npm ci
```

`npm ci` использует точные версии из `package-lock.json` и не изменяет lock-файл.
Для добавления новой зависимости применяется `npm install package-name`.

## Локальный запуск

```powershell
cd frontend
npm run dev
```

Приложение доступно по адресу <http://127.0.0.1:4173/>. Host, port и запрет
автоматического выбора другого порта заданы в `vite.config.ts`.

Стандартный Vite-порт `5173` не используется: на текущей Windows-машине он
попадает в системный зарезервированный диапазон `5141–5240` и завершается
ошибкой `listen EACCES`.

Остановка сервера: `Ctrl+C` в терминале, где выполняется Vite.

## Проверки качества

```powershell
npm test
npm run lint
npm run build
```

Production-образ собирается с Vite base path `/rus-map/`, потому что на staging карта размещена в подкаталоге
существующего сайта. Локальные `npm run dev` и `npm run build` по умолчанию продолжают использовать корень `/`.

- `npm test` один раз запускает Vitest;
- `npm run test:watch` перезапускает тесты при изменениях;
- `npm run lint` запускает ESLint;
- `npm run build` проверяет TypeScript и создаёт production-файлы в `dist`.

Каталоги `node_modules` и `dist` генерируются локально и не входят в Git.

## Карта и внешние ресурсы

`MapView` загружается отдельным JavaScript chunk, создаёт карту при монтировании
React-компонента и вызывает `map.remove()` при размонтировании. Начальный обзор
показывает Россию целиком, минимальный масштаб не позволяет потерять её на фоне
всего мира, а повторяющиеся копии мира отключены. Перемещение к соседним
территориям и размещение там будущих материалов не запрещены. Система координат
долготы и широты соответствует WGS 84.

Для MapLibre chunk задан контролируемый бюджет 1000 kB. Превышение снова вызовет
предупреждение production-сборки и потребует анализа размера.

MapLibre 6 поставляется как ES modules. Для Vite его worker подключён явно через
`?worker&url` и `setWorkerUrl()`. Без этого dev-оптимизатор мог ссылаться на
несуществующий `maplibre-gl-worker.mjs`, из-за чего интерфейс отображался, но
карта не загружалась.

Сейчас используется публичный тёмный стиль OpenFreeMap. Для слоёв с названиями
клиент выставляет приоритет `name:ru`, затем `name:nonlatin`, затем исходного
`name`. Поэтому русское название показывается там, где оно есть в данных
тайлов, а остальные подписи не пропадают.

Региональные границы OpenFreeMap находятся в слое `boundary_state`. После
загрузки стиля клиент делает этот слой светло-серым и немного прозрачным, чтобы
границы областей читались на тёмном фоне, но не конкурировали с маркерами.

OpenFreeMap подходит для прототипа и не требует ключа. Это ещё не окончательный
production-поставщик: перед ростом аудитории нужно повторно проверить условия,
доступность, атрибуцию и при необходимости выбрать сервис с SLA.

## Загрузка мест и маркеры

1. После открытия страницы `App` вызывает `fetchPlaces()`.
2. В разработке Vite передаёт запрос `/api/...` локальному FastAPI на
   `http://127.0.0.1:8000`; в production тот же относительный URL обрабатывает
   Caddy.
3. Клиент проверяет форму ответа и допустимые диапазоны широты и долготы.
4. `placesToGeoJson()` переводит координаты API в порядок GeoJSON
   `[longitude, latitude]`.
5. `MapView` создаёт источник `places` и круговой слой `places-markers`.
6. Клик по маркеру открывает безопасный текстовый popup с названием и передаёт
   UUID выбранного места компоненту `App`.
7. `App` параллельно вызывает `fetchPlace()` и `fetchPlaceMaterials()`, проверяет
   оба ответа API и показывает в боковой панели основную карточку и материалы.

Состояния страницы:

- во время запроса — «Загружаем места…»;
- пустой ответ — «На карте пока нет мест»;
- успешный ответ — количество мест;
- ошибка сети, HTTP или структуры JSON — предупреждение, при этом базовая
  карта продолжает работать.

Для детальной карточки предусмотрены собственные состояния загрузки и ошибки.
Ошибка `GET /api/v1/places/{place_id}` не удаляет карту и маркеры. Карточку можно
закрыть отдельной доступной кнопкой; длинное описание прокручивается внутри
панели и переносит длинные ссылки, поэтому не ломает мобильную вёрстку.

Описание намеренно выводится как обычный безопасный текст, поэтому старые URL
внутри него не кликабельны. Кликабельными становятся отдельные опубликованные
материалы. `PlaceMaterials` поддерживает пять типов:

- `text` — показывает текст с сохранением переносов строк;
- `external_link` — показывает ссылку на внешний источник;
- `image` — показывает ленивое превью и ссылку на оригинал;
- `video` — показывает ссылку «Смотреть видео»;
- `audio` — показывает ссылку «Слушать аудио».

Материалы запрашиваются независимо от основной карточки. Пока запрос выполняется,
пользователь видит «Загружаем материалы…». Пустая коллекция показывает
«Материалы пока не добавлены». Ошибка материалов выводится внутри карточки, но
не скрывает название, описание, карту и маркеры.

Клиент принимает только известные типы и согласованные пары данных: `text`
содержит непустой `content`, остальные типы — HTTP(S)-URL. Некорректный ответ
целиком отклоняется. Перед отрисовкой ссылки протокол дополнительно проверяется.
Все внешние ссылки получают `target="_blank"` и
`rel="noopener noreferrer"`. Произвольный HTML не вставляется, а внешние видео
и аудио не встраиваются в страницу. Это уменьшает риск XSS, стороннего слежения
и поломки вёрстки непроверенным embed-кодом.

Также запланирован поиск по названию места. Он должен показывать подходящие
результаты, открывать выбранную карточку и перемещать карту к её маркеру; точный
контракт поиска будет определён отдельной backend/frontend-задачей.

## Визуальный стиль и права на материалы

Шапка и информационная карточка основаны на графике проекта: угольный фон,
бумажный светлый блок и красный цвет только как небольшой сигнальный акцент.
Заводской знак в `src/assets/factory-mark.png` сделан из изображения,
предоставленного владелицей проекта, с удалением QR-кода, текста и фона.
Упрощённая версия с толстыми линиями и угольным фоном используется как
`public/favicon.png`, чтобы трубы оставались различимыми в маленькой вкладке
браузера. Путь favicon начинается с Vite-переменной `%BASE_URL%`, поэтому
значок работает и локально, и в production-подкаталоге `/rus-map/`.

Для заголовков локально хранится variable-шрифт Oswald с поддержкой кириллицы.
Он распространяется по SIL Open Font License; копия лицензии лежит рядом в
`src/assets/fonts/OFL-Oswald.txt`. Это позволяет собирать интерфейс без загрузки
шрифта со стороннего CDN.

## Частые проблемы

### `npm.ps1 cannot be loaded`

Для текущего пользователя PowerShell разрешить локальные скрипты:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Альтернатива без изменения политики — выполнять `npm.cmd` и `npx.cmd`.

### `Port 4173 is already in use`

Обычно предыдущий Vite-процесс не остановлен. Найти PID слушателя:

```powershell
netstat -ano -p TCP | Select-String ':4173'
```

Перед остановкой процесса обязательно проверить, что PID принадлежит
`node.exe`, запущенному для этого проекта.

### Изменения зависимостей не применились

Остановить Vite и удалить только пересоздаваемый кэш
`frontend/node_modules/.vite`, затем снова выполнить `npm run dev`. Исходный код
и `package-lock.json` удалять не нужно.
