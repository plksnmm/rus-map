# ADR 0003: отдельная схема PostgreSQL для приложения

- Статус: принято
- Дата: 2026-09-02

## Контекст

Образ PostGIS создаёт служебные объекты не только в `public`, но и в схемах
`tiger` и `topology`. При сравнении всей базы с ORM metadata команда
`alembic check` приняла эти объекты за таблицы приложения, удалённые из моделей,
и предложила операции их удаления.

## Решение

Все ORM-таблицы «Руси пролетарской» принадлежат схеме `app`. Alembic включает
сравнение схем, но его autogenerate-фильтр допускает только схему `app`.

Первая содержательная миграция должна создать схему `app` до создания первой
таблицы. Служебные объекты PostGIS остаются под управлением самого расширения.

## Последствия

- автогенерация миграций не предлагает удалить таблицы и индексы PostGIS;
- принадлежность таблиц приложению видна явно;
- запросы и миграции должны учитывать схему `app`;
- создание схемы требуется явно выполнить в первой миграции.
