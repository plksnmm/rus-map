# ADR 0005: HTTPS по IP и публичный API только для чтения

- Статус: принято
- Дата: 2026-09-03

## Контекст

У проекта появился Ubuntu-сервер, но доменного имени пока нет. Приложение нужно показать внешним пользователям,
при этом анонимное создание и изменение мест до реализации авторизации небезопасно.

## Решение

- запускать frontend, backend, миграции и PostgreSQL через отдельный production Compose;
- не публиковать PostgreSQL;
- публиковать внутренние порты frontend и backend только на loopback;
- использовать Nginx как единственную публичную точку входа;
- получать короткоживущий сертификат Let’s Encrypt для публичного IP через Certbot webroot;
- разрешить публично только чтение `/api/`, блокируя изменяющие методы на gateway;
- предоставлять владельцу полный API через SSH-туннель;
- проверять продление сертификата дважды в сутки.

## Последствия

Приложение доступно по доверенному HTTPS даже без домена, а база и изменяющий API не выставлены в интернет.
Сертификат для IP действует только 160 часов, поэтому исправность таймера продления становится обязательной
эксплуатационной проверкой. После реализации ключей участников политика gateway будет расширена отдельным решением.
