# ADR 0002: асинхронный SQLAlchemy и asyncpg

- Статус: принято
- Дата: 2026-09-02

## Контекст

FastAPI обрабатывает запросы асинхронно. Проекту нужен PostgreSQL-драйвер для
локальной разработки на Windows, CI в Linux и будущего production-окружения.
Также требуется единый слой sessions и миграции схемы.

Первоначальная реализация использовала асинхронный Psycopg 3. Проверка реального
соединения на Windows завершилась ошибкой: Psycopg не поддерживает стандартный
`ProactorEventLoop`.

## Решение

Использовать:

- асинхронный API SQLAlchemy 2;
- PostgreSQL-драйвер asyncpg;
- одну SQLAlchemy session на единицу работы или HTTP-запрос;
- Alembic с асинхронным шаблоном и общей metadata моделей.

## Альтернативы

Psycopg 3 можно было оставить, принудительно выбирая SelectorEventLoop на
Windows. Этот вариант отклонён, потому что добавляет платформенное поведение в
точки запуска приложения и тестов.

## Последствия

Положительные:

- одинаковый код подключения на Windows и Linux;
- event loop не перенастраивается глобально;
- сессии и транзакции можно использовать без блокировки event loop;
- изменения схемы будут воспроизводиться через Alembic.

Ограничения:

- integration-тестам требуется запущенный PostgreSQL;
- синхронные инструменты должны использовать async-aware миграционное окружение;
- engine необходимо корректно освобождать при завершении процесса и тестов.
