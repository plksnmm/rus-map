# ADR 0010: серверные сессии для администраторов

- Статус: принято
- Дата: 2026-09-07

## Контекст

Панель премодерации получит полномочия публиковать пользовательский контент. Ей нужны отзыв сессии, защита пароля, CSRF и устойчивое к перезапуску ограничение попыток входа. Публичная регистрация не нужна.

## Решение

Использовать отдельных `AdminUser` и `AdminSession` в PostgreSQL. Пароли хешировать Argon2id через `pwdlib`. Браузеру выдавать случайный непрозрачный session-токен в `Secure`, `HttpOnly`, `SameSite=Strict` cookie, а в базе хранить только SHA-256-хеш. CSRF-токен связать с серверной сессией и требовать в заголовке для изменяющих административных запросов.

Неудачные входы учитывать в PostgreSQL отдельно по хешу логина и адресу клиента. Для неизвестного пользователя всё равно выполнять проверку фиктивного Argon2id-хеша.

## Последствия

- сессию можно немедленно отозвать, а перезапуск приложения не меняет её состояние;
- утечка базы не даёт готовых bearer-токенов;
- каждый аутентифицированный запрос требует чтения PostgreSQL;
- очистку истёкших сессий и старых throttle-записей нужно будет добавить как эксплуатационную задачу;
- при горизонтальном масштабировании не потребуется переносить rate limit из памяти процесса;
- будущая админка обязана передавать CSRF-заголовок и не хранить session-токен в JavaScript.
