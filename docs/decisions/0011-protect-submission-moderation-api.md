# ADR 0011: защищать API модерации сессией, CSRF и узкой Caddy-границей

- Статус: принято
- Дата: 2026-09-09

## Контекст

Очередь `place_submissions` и административные сессии уже существуют, но HTTP-
доступа к решениям не было. Панели модерации нужны чтение недоверенных данных и
изменяющие операции, которые публикуют место. Ошибка маршрутизации или CSRF
может привести к несанкционированной публикации.

## Решение

Чтение очереди и карточки требует действующую серверную административную
сессию. Approve/reject дополнительно требуют session-bound CSRF-токен. Сервис
получает UUID администратора и записывает его вместе со временем решения.

Caddy пропускает наружу только точные POST-маршруты login/logout и
`/admin/submissions/{uuid}/approve|reject`. Другие методы записи продолжают
получать `403` до FastAPI. Backend остаётся второй обязательной границей:
проверяет сессию, CSRF, UUID, состояние заявки и атомарность решения.

## Последствия

- будущая админка может безопасно читать и модерировать очередь;
- решение связано с администратором и не удаляет исходную заявку;
- повторное одобрение не создаёт дубликат;
- публичная отправка заявок и интерфейс администратора остаются отдельными
  задачами;
- старые финальные заявки без администратора сохраняют совместимость через
  nullable-внешний ключ, но все новые решения всегда заполняют его.
