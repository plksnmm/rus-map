# ADR 0006: существующий Caddy и размещение карты по подкаталогу

- Статус: принято
- Дата: 2026-09-03
- Заменяет: ADR 0005

## Контекст

Обследование staging-сервера показало, что Caddy 2.11.4 уже занимает порты 80 и 443 и публикует Vikunja по
предоставленному провайдером имени `vm-1703.lnvps.cloud`. DNS wildcard для отдельного поддомена карты отсутствует.
Запуск второго публичного reverse proxy привёл бы к конфликту портов.

## Решение

- сохранить host-Caddy единственной публичной точкой входа и владельцем TLS;
- оставить Vikunja на корневом URL;
- публиковать карту по `/rus-map/` на том же HTTPS origin;
- собирать production frontend с Vite base path `/rus-map/`;
- направлять `/rus-map/api/*` в backend, удаляя только префикс `/rus-map`;
- блокировать публичные `POST`, `PUT`, `PATCH` и `DELETE` до реализации ключей участников;
- оставить backend и frontend привязанными только к loopback, а PostgreSQL — только к Docker-сети;
- хранить Caddy snippet и пример полного Caddyfile в репозитории и валидировать их в CI.

## Последствия

Не нужны отдельные Nginx gateway, Certbot, новые публичные порты и второй процесс управления сертификатами.
Карта и API используют уже действующий доверенный HTTPS-сертификат Caddy. Приложение зависит от префикса
`/rus-map/`; при появлении отдельного домена base path и Caddy-маршруты потребуется изменить согласованно.
