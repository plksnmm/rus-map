# Тестирование

## Цели

Тесты должны подтверждать пользовательское поведение системы, помогать безопасно
менять код и служить исполняемой документацией API.

## Текущий набор

`tests/test_health.py` отправляет HTTP-запрос через FastAPI `TestClient` и
проверяет статус и JSON-тело ответа `/health`.

Запуск:

```powershell
uv run pytest
```

## Полная локальная проверка

```powershell
uv run pytest
uv run ruff check .
uv run mypy src
```

- pytest проверяет поведение;
- Ruff выполняет статический анализ и проверку стиля;
- mypy проверяет согласованность типов.

## Непрерывная интеграция

Workflow `.github/workflows/ci.yml` запускается для каждого Pull Request в
`main` и каждого push в `main`. На чистом Linux-окружении он:

1. получает исходный код;
2. устанавливает закреплённую версию uv;
3. устанавливает Python из `.python-version`;
4. восстанавливает зависимости строго из `uv.lock`;
5. запускает Ruff, mypy и pytest.

Проверка в Linux дополняет локальную разработку в Windows и помогает обнаружить
зависимость от операционной системы, регистра символов и окончаний строк.

## Будущие уровни тестирования

- unit-тесты бизнес-правил;
- интеграционные тесты API и PostgreSQL/PostGIS;
- проверки схемы OpenAPI и контрактов;
- E2E-сценарии пользовательского интерфейса;
- тесты ролей, доступа и модерации;
- проверки загрузки файлов и географических данных.

Предупреждения тестового запуска считаются проблемами и устраняются, а не
скрываются глобальными фильтрами.
